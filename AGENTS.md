# AGENTS.md

This file provides guidance to AI coding agents when working with code in this repository.

Monke is a client-only word generator for conlang creators (React 19 + TypeScript + Vite + Tailwind 4), served at https://monke.lunah.dev/.

## Commands

- `npm run dev` — Vite dev server
- `npm run build` — `tsc` type-check, then `cf build` (Vite build with the Cloudflare plugin; output in `.cloudflare/output/v0/`)
- `npm run lint` — ESLint, `--max-warnings 0`
- `npm run preview` — serve the production build
- `npm run preview:cf` — `cf dev`, local Workers runtime
- `npm run check:prerender` — after a build, checks the prerendered pages and crawler files (run in CI)
- `npm test` — Vitest (jsdom), single run; `npm run test:watch` for watch mode

Tests are colocated as `*.test.ts(x)`: engine tests (pattern, buildGrammar, generate, configReducer, sharing, features) plus UI tests in `src/app/` (`Home`, `reorder`, `semantics`, `a11y`) and next to the features (`GrammarToolbar`, `RuleCard`, `FeaturesPanel`, Awkwords import). `src/test-setup.ts` polyfills jsdom gaps (tests render the desktop layout; override `matchMedia` for the mobile one) and `src/app/test-helpers.ts` drives the toolbar and view settings menus.

## Architecture

Data flows: UI config → grammar AST → generated words.

- **Layout**: `src/engine/` is pure TS (no React) and holds everything below except UI. `src/app/` is the shell (`App`, `Home`, `Navbar`, `useUrlConfig`). `src/features/{config,generator,docs}/` hold the feature UI: `GrammarToolbar` (language, start rule, flags, New/Examples/Import/Export/Share) sits under the header, then the Phonological features panel and the rule cards (`Configuration`) and the output panel (`Generator`); the output panel comes first on small screens, and `Home` orders the DOM to match. `useGeneratorView` holds the viewer-only output state (word count, paragraph/list, filter duplicates, import notes) shared by the toolbar's Awkwords import and the output panel. `src/components/` holds small layout primitives (`Row`, `Col`, `Linear`, etc.) and `SortableList`/`SortableRow`, the shared dnd-kit sorting wrapper. `@/` aliases `src/` (tsconfig `paths` + Vite `resolve.alias`); engine files use relative imports.
- **`Config`** (`src/engine/config.ts`, with the UI rule types) is the single app state: language name, root rule, rules, weight/serif flags. `useUrlConfig` owns it via `useReducer(configReducer)`; panels receive `config` and `dispatch`. All mutations are typed `ConfigAction`s handled in `src/engine/configReducer.ts` (rules addressed by id; new items get ids there). Add new mutations as an action plus a reducer test. The app is a single page with no router: the URL path is read once at startup.
- **Rewrites / Exclusions toggles** (the `Rewrites` / `Exclusions` buttons on a pattern rule) are enable switches: when off, the generator ignores that rule's rewrites or exclusions (the entries are kept in the config). This is intended.
- **Pattern parser** (`pattern.ts`): `Parser` turns one pattern string into an `Expr` AST (`grammar.ts`). **Grammar builder** (`buildGrammar.ts`): `configToGrammar` parses each rule, validates rule names and references, and applies the Rw/Ex enable flags. Terminal-only rules skip parsing; their patterns are literal atoms. Errors are thrown with the rule name appended (parse errors also end with `at character N`) and surfaced to the user: in the global alert and, via `InlineGrammarError`, under the input at fault. Unknown rule names suggest the closest name (`suggest.ts`, Levenshtein ≤ 2); the parser reports adjacent terms as a missing `.`.
- **Pattern syntax**: `'atom'` (with `\` escapes), `Ref` (rule name), `a.b` sequence, `a / b` choice, `*N` weight, `(x)` optional (default weight 0.5, `(x*0.3)`), `[x]` group, `x{n}` / `x{min:max}` quantifier, `#n#` back-reference to part n of the match's top-level sequence (inserts it in rewrite replacements; matches the same text again in rewrite matches and exclusions, where it must follow part n), `^` / `$` zero-width start/end of the rule's output (rewrite matches and exclusions only; counted as an empty back-reference part), `Ref<front, !back>` feature filter (see Phonological features).
- **Phonological features** (`features.ts`): `Config.features` declares features with weighted values; pattern rows (`RulePattern.values`) and whole rules (`Rule.values`) carry value ids, and `Rule.chooses` lists feature ids (absent = none; ids, so renames touch nothing, and removing a feature/value strips it from every item in the reducer). `configToGrammar` turns ids into names (`Tags`: feature → values) on `WeightedExpr.tags` (a rule's rows) and `Rule.tags`/`chooses`; value names are unique across the grammar so filters name them alone. Semantics: on entering a rule, each chosen feature gets a value (weighted only when Weights is on); in its subtree every alternative carrying other values of that feature is removed (an untagged item is neutral and stays; a `Ref` alternative carries its rule's values; inner rules may re-choose). `Ref<front, !back>` keeps the referenced rule's rows that are (not) members, in generation, rewrite matches and exclusions; matching has no scope. `checkFeatures` walks every (rule, chosen values, filters) state from the root and throws a located error for a tagged item reached where its feature is neither chosen nor filtered at that spot, and for scope/filter dead ends; `featureWarnings` lists unused features and choices nothing below reacts to. Errors on a rule's values/chooses controls use the `RULE_VALUES_ITEM`/`RULE_CHOOSES_ITEM` item ids, errors on declarations use the feature id as the owner. Generation draws no extra random numbers for rules without choices, so old seeds give the same words. `countCombinations` sums derivations over every chosen value (an upper bound, as before); `enumerate` unions the words of every value.
- **Generator**: `generate.ts` does recursive random expansion from the root rule (weighted picks only if `useWeights`) and takes an injectable `rng` (default `Math.random`). `seed.ts` has `mulberry32` and `seededRng` (hash of `Config.seed`); output is a pure function of (grammar, seed, word count), so the Generator redraws automatically (debounced for grammar edits, immediate for seed/word-count changes) and never exposes a Generate button. Config loaders (`load`, `clear`, `loadExample`, initial state) fill in a random seed via `withSeed`/`randomSeed`, so old links and files without a seed get one. "New words" sets a new random seed and is announced, as is Generate all; automatic redraws are deliberately silent. Per rule, rewrites are applied to the output, then it is retried if it matches an exclusion. `match.ts` is the backtracking matcher (a generator yielding per-sub-expression match lengths that feed `#n#`); empty overall matches are ignored when scanning. `analysis.ts` has `countCombinations` and `detectCycle` (DFS from the root). `enumerate.ts` lists every distinct word (Generate all), mirroring generation's rewrite/exclusion logic, bounded by a word limit and a work budget; the UI runs it in a Web Worker (`features/generator/listAll.ts`). `Grammar.ruleMap` is the name lookup for `Ref`s.
- **Sharing** (`sharing.ts`, `bytebuffer.ts`): the whole `Config` is serialized to a versioned binary format, compressed to base64, and kept in the URL path (`/<data>`). `useUrlConfig` decodes the path on load and on `popstate`, and mirrors config changes into the URL with a debounced `history.pushState`, so browser Back/Forward act as undo/redo. Decoding dispatches on the version byte through a per-version table; encoding always writes the latest. Changing `Config` or rule fields requires a new version: add a decoder (never edit shipped ones), bump `LATEST_VERSION`, update `encodeConfig`, and add a frozen-link test. Routing: static files and prerendered pages are served first (`/faq` redirects to `/faq/`); only paths without a matching file reach the Worker (`src/worker/index.ts`, `entrypoint` in `cloudflare.config.ts`), which serves `index.html` (200) when `configSegment` reads a share link and the prerendered `404.html` with status 404 for anything else (`/foo.json`, `/.well-known/*`, `/a/b`). `notFoundHandling` must stay `"none"`: with a fallback configured, browser navigations that miss skip the Worker, which would break share links or the 404s.
- **Static pages** (`src/site/`): `/reference/`, `/faq/` and `/awkwords-alternative/` are prerendered at build time by the `site()` Vite plugin (`scripts/site.ts`) from the same components and data as the in-app views (`ReferenceContent`, `faqItems`, `referenceExamples.ts`), into `<path>/index.html` with their own title, description, canonical and (FAQ) FAQPage JSON-LD; it also writes `llms-full.txt`. They are plain documents without the app bundle; the in-app Reference/FAQ tabs are unchanged. Pages are listed in `staticPages` (`pages.ts`); add one there, in `StaticPageBody`, `navLabel`, `public/sitemap.xml` and `public/llms.txt`. Their paths contain `/`, which share links (base64url plus `~` padding) never do; `configSegment` is the only way to read a config from the path. Everything rendered there must work without effects. The 404 page (`notFoundPage`, `NotFoundBody`) is prerendered the same way to `404.html`, with `noindex` and no canonical, and is not a static page.
- **SEO**: `index.html` has a static canonical to `/`, so every share link canonicalizes to the home page. Share links are deliberately not `noindex` and not disallowed in `robots.txt`: links posted elsewhere are backlinks, and canonical consolidates them (Google advises against combining noindex with canonical). Static pages are self-canonical. `public/robots.txt`, `sitemap.xml` (update `lastmod` when pages change) and `llms.txt` are plain files. `public/.well-known/ai-catalog.json` is an ARD (Agentic Resource Discovery, https://agenticresourcediscovery.org/spec/) catalog, checked by Lighthouse's Agentic Browsing category: `specVersion` "1.0", a `host`, and an empty `entries` array, because Monke publishes no agent resources (no MCP server, agent card or skill). Add entries only for real ones; `check:prerender` checks its shape.
- **Analytics privacy**: the path holds the grammar, so analytics must never see it. The head script in `index.html` reports `analyticsPageUrl` (`pages.ts`, inlined by the build) to GA: `/` and static pages as is, anything else as `/shared`; the title is fixed. gtag's enhanced measurement reports pushState/popstate with the raw address, so `useUrlConfig` writes the URL through `window.monkeHistory` (native methods saved before gtag loads) and listens to `monke:popstate` (popstate is stopped before gtag sees it). `<meta name="referrer" content="strict-origin">` keeps the path out of referrers. The Cloudflare beacon loads everywhere (Cloudflare already serves every request and sees the path; `spa: false` so edits are not navigations). Keep these when touching history or analytics.
- **Fonts**: self-hosted variable fonts from `@fontsource-variable/*` (upright only), imported in `main.css`; the build preloads the Latin Noto Sans file.
- **Config files**: `configfile.ts` validates `.monke` files imported from the Generator panel. The Toki Pona example grammar and `emptyConfig`/`defaultConfig` are in `defaults.ts`. State updates are immutable (`patchById`/`removeById`/`moveItem` in `list.ts`).
- **Design tokens** live in the `@theme` block of `main.css`: neutrals, one teal primary, and one hue per kind of thing (terminals sky, patterns violet, rewrites amber, exclusions orchid, features lime, delete red) that is never reused for anything else. Pattern, terminal, rewrite, exclusion and seed text is `font-mono` (JetBrains Mono), swapped for `font-serif` by the serif setting. Shared control classes are in `components/styles.ts`; menus are Headless UI `Menu`s styled in `components/menu.tsx`.
- **Main dependencies**: React, dnd-kit (sorting), Headless UI (menu, listbox, radio group, dialog), lucide-react (icons; brand icons are inlined), react-toastify, react-autowidth-input, base64-compressor (share links).

## Accessibility

Screen reader users (NVDA, TalkBack) are core users. Every change must keep these true:

- **Names**: every control has an accessible name that locates it (`Delete pattern 2 of rule Vowel`, not `Delete`). Names stay constant when state changes; state goes in `aria-checked`, `aria-pressed` or `aria-expanded`. Icon-only buttons need `aria-label`; visible text must be part of the name.
- **Keyboard**: everything is operable with the keyboard and has a visible focus ring (global `:focus-visible` in `main.css`).
- **No drag-only features**: anything draggable also has buttons. Sortable items get `MoveButtons` (left/right for horizontal exclusion chips, up/down for rules and for the rows of terminals, patterns and rewrites) and the list a `describe` for dnd-kit announcements. Rule buttons are always shown on wide screens (a `More actions` menu holds them on small ones); row and chip buttons are collapsed to zero width until the chip contains keyboard focus (`:focus-visible`; never `display:none`, so they stay in the tab order). Never reveal on hover: it shifts targets under the pointer; the viewer setting "Always show reorder buttons" (in the output panel's View settings menu; `reorderPref.ts`, localStorage, not in `Config`) keeps them visible.
- **Announcements**: results and state changes that appear without focus moving go through a live region (`role="status"` for results, `role="alert"` for errors). Announce a summary, never a long list. Grammar errors also set `aria-invalid` and `aria-describedby` on the input at fault (`useInvalidProps`).
- **Structure**: one `h1`, no skipped heading levels, landmarks (`header`, `nav`, `main`). Examples in the Reference are real text (`<code>`, lists, tables with `<th scope>`), not fake controls; their data lives in `referenceExamples.ts` and is checked against the engine by `referenceExamples.test.ts`.
- **No hacks for character reading**: do not insert spaces or separators between letters. Screen readers have character modes.

Verify: `npm run lint` (jsx-a11y, no disables without a stated reason) and `npm test`. `src/app/a11y.test.tsx` runs axe on each main view and state; add a case for any new view or state. jsdom can't compute colour contrast, so check it in a real browser by running axe-core there, and drive the page with a screen reader or Playwright `ariaSnapshot()` for names and order. Every text/background pair in the palette is at least 4.5:1 (checked by computing ratios; keep that when adding colours). Input borders are quiet by design and the fields are also identified by their labels and fill.

## Deployment

- Hosted as a Cloudflare Worker with static assets (`monke`); the Worker script only runs on asset misses (share links and 404s), built and deployed by Workers Builds (Git integration). Custom domain is set via `domains` in `cloudflare.config.ts`.
- Use the `cf` CLI (devDependency), not wrangler. Config is `cloudflare.config.ts`; `cf` ignores `package.json` scripts, so `npm run build` chains `tsc && cf build`.
- Workers Builds: build command `npm run build` (or `npx cf build`), deploy command `npx cf deploy`. Validate locally with `npx cf deploy --dry-run`.
- `public/_headers` sets cache headers (immutable for `/assets/*`, revalidate for HTML, an hour for the crawler files and `ai-catalog.json`), UTF-8 for `.txt`, and `application/json` for the catalog.
- The prerender runs inside the Vite build, so both `npm run build` and `npx cf build` produce the static pages.
- `.cloudflare/` is generated output and gitignored.
